# Mühür Faz 2.5 — Prototip Görsel Kimliği Uygulaması Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the plain functional CSS/markup of the four existing, already-wired frontend pages (order form, login, orders list, workspace) with the real Mühür prototype's visual design system (Apple-Design-inspired: Fraunces/Inter/IBM Plex Mono fonts, bronze accent, card/panel components) — with zero change to the JS business logic (the `fetch` calls, request/response handling) that Faz 2/3 already built and verified against the real backend.

**Architecture:** One shared `public/styles.css` is rewritten wholesale, pruned from the two real prototype files (`~/Downloads/muhur-prototip-v5.html`, `~/Downloads/muhur-prototip-v6-calisma-alani_1.html`) down to only the selectors these four pages actually use. Each page's HTML markup is rewritten to use the prototype's component classes (`.card`, `.field`, `.panel-shell`, `.compare-col`, `.suggest-panel`, etc.) while every element `id` that the existing `.js` file already queries (`#name`, `#email`, `#orders-body`, `#final-text`, `#suggest-btn`, etc.) is preserved exactly, so the JS files need no logic changes — only the handful of small, explicitly-called-out visual glue additions (a dropzone click-to-upload handler, a suggest-empty-state toggle) described in each task.

**Tech Stack:** Same as Faz 1/2/3 (Fastify serving static files, vanilla JS, no build step). Google Fonts CDN (Fraunces, Inter, IBM Plex Mono) added via `<link>` tags, matching the prototype exactly.

## Global Constraints

- **No JS business logic changes.** Every `fetch(...)` call, every request body, every response-handling branch (401 redirect, error message display, status code checks) in `order-form.js`, `login.js`, `orders.js`, `workspace.js` must remain byte-identical to its current form, UNLESS a task explicitly shows the exact small addition (dropzone glue, suggest-empty toggle) — these are the only two logic additions in this whole plan, and both are visual/DOM-only, not new API calls.
- **Every element `id` referenced by existing JS must be preserved.** Before changing any HTML file, grep the paired `.js` file for `getElementById`/`querySelector` calls and make sure every id/selector it uses still exists in the new markup.
- **No `innerHTML` with dynamic (user- or AI-supplied) content** — same rule as Faz 2/3. Use `textContent` or `document.createElement` + `.textContent`. This plan's JS additions follow this rule; do not regress existing code that already follows it (e.g. `orders.js`'s row-building, `workspace.js`'s suggestion-list building).
- **No AI-provider multiplexing.** The workspace page shows exactly one AI tab, labeled "Gemini" — do not add ChatGPT/Mistral/DeepL tabs or per-provider suggestion labels; the real backend has one provider.
- **No new pricing fields.** The order form does not gain page-count, urgency, notary, or apostille controls — those have no backend support (see design spec's "Kapsam Dışı"). Only cosmetic restyling of the existing name/email/language/file-or-text fields.
- **No sidebar mock categories.** `orders.html`/`workspace.html`'s `.panel-side` shows only the real "Siparişler" link (and, on the workspace page, a "Çalışma alanı" label for the current page) — never the prototype's fake "İncelemede (3)", "Notere gidecek (1)", etc.
- **No `proto-nav` / `go()` view-switcher.** The prototype's single-file, multi-view JS navigation is not ported — each page is its own real HTML file, unchanged from Faz 2's "no build tool" decision.
- Postgres runs via Docker on host port `5433`; Prisma is pinned to `6.19.3`; run the dev server with `npx dotenv -e .env -- npm run dev` from `muhur-backend/`. Unchanged from Faz 1 — see that plan's Environment Notes if anything fails.
- No automated frontend tests. Each task's verification step is a `curl` 200 check (and a `grep` confirming key selectors exist where noted); the final task is a real browser walkthrough using the `mcp__Claude_Browser__*` tools.
